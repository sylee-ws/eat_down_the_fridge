# 도메인 규칙

## 용어

| 용어 | 뜻 |
|---|---|
| 냉장고 재료 | 사용자가 **선택한** 재료 태그. 선택 안 된 태그는 "없는 것"이다. |
| 보유 양념 | 사용자가 **체크한** 양념. 체크 안 된 양념은 "없는 것"이다. |
| 가진 것 | 냉장고 재료 ∪ 보유 양념 ∪ {물}. 물은 항상 가진 것. |
| 못 먹는 재료 | 제외 단어 목록(알레르기 포함). 이름에 그 단어가 들어간 것까지 막는다. |
| 후보 | AI가 만든 레시피 1개. |
| 후보판 | 한 번의 생성 요청(보충 포함)으로 받은 후보 묶음. 룰렛 칸이 된다. |
| 부족 재료(장바구니) | 레시피 재료 중 가진 것에 없는 것. 앱이 계산한다. |
| 이름 정규화 | 앞뒤·내부 공백을 모두 지운 문자열. 모든 이름 비교는 정규화 후에 한다("참치 캔" = "참치캔"). |

## 레시피 모양

요리명, 불 사용 시간(정수 분), 손질 시간(정수 분), 기준 인분(1~4), 재료 목록(이름·수량·단위), 조리 순서. 수량이 없는 재료(약간/적당량)는 수량 null + 단위 "약간"/"적당량"이며 환산하지 않는다.

## 부족 재료 계산

- 입력: 레시피 재료 목록, 선택 재료, 보유 양념 → 출력: 가진 것에 없는 재료 목록.
- 레시피 재료 순서를 유지하고, 같은 이름(정규화 기준)이 여러 줄이면 첫 줄만 남긴다.
- `밥`도 일반 재료다. 선택하지 않았으면 부족 재료가 된다.
- 결과 카드, 즐겨찾기, 후보판 재검사, 서버 후보 검사가 모두 같은 계산을 쓴다. AI가 "부족"이라고 표시한 값은 없다(요청하지도 않는다).

## 후보 검사 (하나라도 어기면 그 후보는 버림)

생성 시점에만 보는 규칙:
1. 요리명이 비어 있지 않고 정규화 후 40자 이하. 같은 후보판(보충분 합칠 때 기존 후보 포함) 안에서 요리명이 겹치면 뒤의 것을 버린다 — 겹침 판정은 다른 규칙을 모두 통과한 후보끼리만 한다.
2. 불 사용 시간은 정수 0~15분, 손질 시간은 정수 0~10분. (15분은 통과, 16분은 탈락. 7.5분처럼 정수가 아니면 탈락)
3. 조리 순서 3~4단계, 빈 단계 없음.
4. 재료 1개 이상, 이름이 비어 있지 않음, 수량은 null 또는 0보다 큰 수.
5. 요리명이 피할 이름 중 하나와 정규화 후 같지 않음.

조건에 따라 달라지는 규칙 (생성 시점 + 조건이 바뀔 때마다 다시 적용):
6. 선택된 냉장고 재료를 1개 이상 쓴다. 양념만 쓰는 후보는 불인정.
7. 부족 재료 3개 이하 (0개 가능, 4개면 탈락).
8. 못 먹는 재료 위반이 없다.

서버는 AI가 보낸 인분 값을 무시하고 요청한 인분으로 덮어쓴 뒤 검사한다.

## 못 먹는 재료

- 위반: 제외 단어 w가 요리명 또는 어떤 재료 이름에 **포함**되면(정규화 후) 위반. 새우 → "새우젓", "새우볶음밥" 모두 위반. 빈 제외 단어는 무시.
- 이름으로 잡히지 않는 파생 재료(우유 → 버터·치즈·크림)는 AI 지시로만 막는다. 그래서 제외 섹션과 결과 카드에 "AI가 만든 레시피예요. 알레르기 재료는 꼭 한 번 더 확인하세요." 안내가 항상 붙는다.
- 태그: 이름에 제외 단어가 들어간 재료 태그·양념은 흐리게 보이고 선택/체크할 수 없다. 제외 단어를 추가하는 순간 이미 선택·체크된 해당 태그는 자동 해제된다. 제외 단어를 지우면 다시 선택할 수 있지만 자동으로 다시 선택되지는 않는다.
- 제외 단어에 걸리는 이름은 직접 입력 태그로도 만들 수 없다.

## 태그·목록

- 기본 재료 태그 19개, 기본 양념 15개(처음 설치 시 소금·설탕·간장·식용유·후추 체크). 기본 태그는 삭제 불가.
- 직접 입력: 정규화 후 빈 값은 무시, 20자 초과는 거부. 기본/직접 태그와 같은 이름이면 새로 만들지 않고 그 태그를 선택한다. 새 태그는 만들어지면서 바로 선택/체크된다. 직접 입력 태그는 삭제할 수 있고, 삭제하면 선택도 풀린다.
- 개수 한도: 선택 재료 30개, 체크 양념 30개, 못 먹는 재료 30개. 넘으려 하면 선택·추가하지 않고 "최대 30개까지예요". 이 한도는 서버 요청 한도와 같아야 한다.
- 인분: 1~4, 기본 2.

## 후보판과 룰렛

상태: 현재 후보판, 이 판에서 이미 결과로 나온 후보, 이번 사용 중 판에 올랐던 요리명 기록(오른 순서, 같은 이름이 다시 오르면 가장 최근 자리로 이동). 모두 메모리에만 있고 새로고침하면 사라진다.

- 남은 후보 = 판의 후보 − 이미 나온 후보.
- 돌리기/다시 돌리기: 남은 후보 2개 이상 → 남은 후보 중 균등 확률로 당첨을 먼저 정하고 룰렛이 그 칸에 멈춘다. 1개 → 룰렛 없이 바로 결과("후보가 하나뿐이에요"). 0개 → 다시 돌리기 대신 "새 후보 받기"만.
- 결과로 나온 후보는 "나온 것"이 되어 남은 후보에서 빠진다.
- 남은 후보가 2개 미만이면 "새 후보 받기"를 제안한다.
- 새 후보 받기(와 이후의 돌리기): 요리명 기록의 **가장 최근 50개**를 피할 이름으로 보낸다. 새 판이 이전 판을 대체하고, 기록은 계속 쌓인다.
- 생성 결과가 0개면 "조건에 맞는 요리를 못 찾았어요. 재료를 더 고르거나 제외를 줄여 보세요." + 다시 시도.
- 조건 변경 재검사: 판이 있는 상태에서 선택 재료·보유 양념·못 먹는 재료가 바뀌면 남은 후보에 규칙 6~8을 다시 적용해 안 맞는 것을 뺀다(이미 나온 후보는 그대로). 새 판이 도착했을 때도 그 사이 바뀐 조건으로 한 번 재검사한다.
- 이미 떠 있는 결과 레시피는 조건이 바뀌어도 사라지지 않는다. 그 장바구니만 현재 조건으로 다시 계산된다.

## 인분 환산

- 기준 인분 b의 레시피를 인분 n으로 보여줄 때 수량 = 수량 × n / b. 수량 null은 그대로.
- 반올림(표시·문구 단계에서 **항상**, n = b여도): 10 미만은 0.5 단위, 10 이상은 정수, 결과가 0이면 0.5. (AI가 준 0.3큰술 → 0.5큰술, 150.6g → 151g)
- 결과 카드: 전역 인분을 바꾸면 즉시 환산(AI 호출 없음). 다음 요청에도 그 인분이 쓰인다.
- 즐겨찾기 카드: 저장 당시 인분으로 열리고, 카드 안에서 바꿔도 저장값은 그대로.

## 장바구니 문구 (글자 단위 고정)

```
🛒 장바구니 — {요리명} ({인분}인분)
- {재료명} {수량}{단위}
- {재료명} {단위}          ← 수량이 null일 때 (예: 후추 약간)
```
살 것이 없으면: `🛒 {요리명}: 살 재료 없음! 냉장고 재료로 충분해요`. 문구의 수량은 표시 인분으로 환산·반올림된 값이다. 한 번에 레시피 1개분만 — 여러 레시피 합치기는 없다(현재 상태).

## 공유·복사

- 공유 버튼은 기기가 기본 공유창을 지원할 때만 보인다. 사용자가 공유창을 닫으면 알림 없음, 그 밖의 실패는 "공유하지 못했어요".
- 복사 버튼은 항상 보인다. 성공 "복사했어요", 기본 클립보드 실패 시 대체 복사, 그것도 실패하면 "복사하지 못했어요".

## 즐겨찾기

- 결과 카드의 ♡로 저장/해제(같은 레시피 id면 토글). 저장 내용: 레시피 전체 + 당시 표시 인분 + 저장 시각. 최근 저장이 맨 위.
- 열면 겹쳐 뜨는 별도 카드. 현재 결과와 후보판은 그대로 남는다. 버튼은 공유·복사·♡·닫기뿐(다시 돌리기·새 후보 없음). ♡로 해제해도 카드는 열린 채로 남고 다시 누르면 다시 저장된다.
- 장바구니는 **지금의** 선택 재료·보유 양념 기준으로 다시 계산한다.
- 목록에서 삭제 가능, 수정 불가, 개수 제한 없음.

## 가족 암호 (화면 동작)

- 기기에 저장된 암호가 없으면 첫 화면은 암호 입력. 서버가 맞다고 하면 기기에 저장하고 본 화면으로, 틀리면 "암호가 달라요".
- 후보 요청이 401이면 저장된 암호를 지우고 암호 화면으로 돌아간다(가족 암호가 바뀐 경우).
- 암호는 입력한 그대로 보낸다(앞뒤 공백도 자르지 않음).

## 기기 저장

- 기억하는 것: 선택 재료, 직접 입력 재료, 체크 양념, 직접 추가 양념, 못 먹는 재료, 인분, 즐겨찾기, 가족 암호. 기억하지 않는 것: 후보판, 현재 결과.
- 저장값이 없거나 JSON이 깨졌거나 버전이 다르면 전부 기본값. 일부 칸만 이상하면 그 칸만 기본값. 저장소를 못 쓰는 환경이면 저장 없이 동작.
- 가족 각자의 기기는 각자의 설정을 가진다(공유·동기화 없음 — 현재 상태).
