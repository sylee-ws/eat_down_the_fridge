# 풀지 못한 문제

## 실제 AI 회사 API로 확인되지 않은 응답 형식
- 상태: 세 회사 연결부는 가짜 SDK 응답으로만 테스트됐다. 수량의 null 허용을 `type: ["number","null"]`로 표기한 스키마를 실제 OpenAI strict 모드·Gemini가 받아들이는지, 기본 모델 이름(Google `gemini-3.5-flash-lite`, OpenAI `gpt-5.4-mini`)이 실제 계정에서 호출되는지 미확인. Google 기본 모델은 설치된 SDK의 모델 목록에는 없고(목록의 최신 소형은 `gemini-3.1-flash-lite`) 공식 문서 요약으로만 확인됐다.
- 영향: 형식이나 모델 이름이 거부되면 그 회사로 설정했을 때 모든 돌리기가 "레시피를 못 가져왔어요"(502)가 된다. 서버 로그에 회사·모델·오류 요약이 남는다.
- 지금 못 푸는 이유: 실제 키가 없다(사용자 계정 필요, 사용료 발생).
- 방법: 키를 넣고 회사별로 한 번씩 돌려 본다. 모델 이름 문제면 `AI_MODEL`로 바로 바꿀 수 있고, 스키마 문제면 그 회사 연결부에서 스키마를 변환한다.

## 실제 폰에서 복사 대체 경로 미확인
- 상태: 자동화 브라우저에서는 기본 클립보드와 대체 복사가 모두 실패해 "복사하지 못했어요"가 나왔다(포커스 없는 창의 권한 문제로 추정). 대체 복사는 기본 클립보드 실패를 기다린 뒤 실행되므로, "사용자 탭 직후에만 복사 허용"하는 브라우저에서는 대체 경로도 거부될 수 있다.
- 영향: 그런 브라우저에서 기본 클립보드가 없거나 막혀 있으면 복사가 안 되고 실패 알림만 뜬다(공유 버튼은 별개로 동작).
- 지금 못 푸는 이유: 실제 기기 확인이 필요하다.
- 방법: 폰·PC 실기기로 복사 확인. 문제가 있으면 기본 클립보드가 없을 때는 기다리지 않고 바로 대체 복사를 부르도록 순서를 바꾼다.
